# ANDROID-ABI.md — CLEF Android ABI Contract

CC0 1.0 Universal — public domain. See LICENSE.

This document is the **ABI contract** between the CLEF runtime (`libclef.so`)
and the Android platform shim that loads it. It is written to be satisfied by
a thin platform shim, mocked on Linux for host-side testing. The CL side never
calls NDK APIs directly.

Normative references: DESIGN.md §9.2, Android NDK `native_activity.h`,
`android_native_app_glue` (for shape only — we ship no Java/dex stub).

---

## 1. Artifact shape

- **Binary:** `libclef.so` — static shared object, **no `DT_NEEDED`** entries.
  All runtime dependencies are resolved at load time by the platform shim via
  the contract below, not by the dynamic linker.
- **Packaging:** loaded by a `NativeActivity` APK with
  `android:hasCode="false"`. There is genuinely no Java/dex stub in the CLEF
  tree. The APK's `android.app.lib_name` meta-data names the `.so`.
- **Entry point:** the single exported symbol is
  `ANativeActivity_onCreate`, written in Common Lisp.

```
APK (no dex)
 └── lib/aarch64/libclef.so          ; static, no DT_NEEDED
      └── ANativeActivity_onCreate   ; the only export
```

## 2. API floor

- **API 30+ (Android 11)** is the floor.
  - `memfd_create` (API 30) → W^X dual mapping.
  - 16 KB page support mandatory on new devices (API 31+); we target both
    4 KB and 16 KB kernels from day one.
  - Stable SELinux `execmem` policy (API 29+).

## 3. Memory: W^X and code generation

The JIT writes machine code. Android enforces W^X: a page is never writable
and executable at once. The contract is **dual mapping**:

1. `memfd_create("clef-code", MFD_CLOEXEC)` → an anonymous in-memory fd.
2. `ftruncate` to the code-region size.
3. `mmap` the fd twice:
   - **RW mapping** (`PROT_READ|PROT_WRITE`, `MAP_SHARED`) — the JIT writes here.
   - **RX mapping** (`PROT_READ|PROT_EXEC`, `MAP_SHARED`) — the CPU executes here.
4. The two mappings share the same backing pages; a write through RW is
   immediately visible through RX (no `mprotect` flipping, no cache-sync
   beyond the standard `__builtin___clear_cache` equivalent on aarch64).

**Fallbacks** (in order): ashmem dual-map, then `mprotect` RW↔RX flipping
around each JIT emission batch (slower, but works on kernels without
`memfd_create` — below API 30, outside our floor).

**16 KB alignment:** every `PT_LOAD` segment in the `.so` is aligned to
**16384** bytes (Play requirement for native code). Code regions allocated via
`memfd_create` are page-aligned by construction.

## 4. The shim contract

The platform shim (a small amount of code, **not in the CLEF tree's CL
toolchain** — mocked on Linux) provides the following. The CLEF runtime calls
these through generated C-ABI trampolines (no libffi).

### 4.1 Provided by the shim → called by CLEF

| Symbol | Signature (C ABI) | Purpose |
|--------|-------------------|---------|
| `clef_shim_alloc_code` | `void* (size_t size, void** rx_out)` | Dual-mapped code region: returns RW base, writes RX base to `rx_out`. |
| `clef_shim_free_code` | `void (void* rw, size_t size)` | Tear down both mappings. |
| `clef_shim_log` | `void (int prio, const char* tag, const char* msg)` | `__android_log_write`. |
| `clef_shim_looper` | `void (int (*callback)(int fd, int events, void* data), void* data)` | Register the main-loop callback on the activity looper. |
| `clef_shim_window` | `void* (void)` | Current `ANativeWindow*`, or NULL before `APP_CMD_INIT_WINDOW`. |
| `clef_shim_read_asset` | `int (const char* name, void** buf_out, size_t* len_out)` | Read an APK asset into a malloc'd buffer. |

### 4.2 Provided by CLEF → called by the platform

| Symbol | Signature | Purpose |
|--------|-----------|---------|
| `ANativeActivity_onCreate` | `void (ANativeActivity*, void* savedState, size_t savedStateSize)` | The one export. Initializes the runtime, installs the looper callback, enters the event loop. |

### 4.3 Lifecycle events the runtime must handle

Delivered through the looper callback as `APP_CMD_*` equivalents:
`INIT_WINDOW`, `TERM_WINDOW`, `GAINED_FOCUS`, `LOST_FOCUS`, `PAUSE`, `RESUME`,
`DESTROY`, plus `LOW_MEMORY` (must trigger a GC request). The runtime treats
`TERM_WINDOW` + re-`INIT_WINDOW` as a surface swap, not a restart.

## 5. JNI bridge (outbound calls)

CLEF calls into the Android framework (UI, clipboard, etc.) via JNI. The
contract:

- JNI functions are invoked through **C-ABI trampolines generated by the
  JIT** — no libffi, no handwritten assembly per call site.
- The trampoline layer knows `JNIEnv*` is always the first argument, and the
  `JNICALL` convention (on aarch64: standard AAPCS64; on x86-64: SysV).
- Object references crossing the boundary are held as JNI global refs and
  freed by the runtime's finalizer pass.

The UI DSL (`src/android/ui.lisp`) is specified against this bridge and goes
live when the aarch64 backend exists.

## 6. SELinux and `execmem`

API 29+ stabilizes the `execmem` policy for app domains. The dual-mapping
approach in §3 stays within the app-domain allowance: the RX mapping of an
app-created `memfd` is permitted executable. The contract requires the shim to
probe once at startup (`mmap` a scratch `memfd` RX) and abort with a clear log
message if the policy denies it, rather than failing obscurely mid-JIT.

## 7. Host-side mock (Linux)

For host testing, the shim is satisfied by a Linux mock:

| Shim call | Linux mock |
|-----------|------------|
| `clef_shim_alloc_code` | `memfd_create` + double `mmap` (same as target — Linux has had `memfd_create` since 3.17). |
| `clef_shim_log` | `fprintf(stderr, ...)`. |
| `clef_shim_looper` | A stub pumping a fixed script of lifecycle events. |
| `clef_shim_window` | Returns NULL (headless). |
| `clef_shim_read_asset` | `fopen`/`fread` from a test directory. |

The mock proves the runtime's half of the contract compiles, links, and runs
its lifecycle state machine without a device.

## 8. What this contract deliberately does NOT specify

- The instruction encodings (that's the aarch64 backend, issue #9).
- The CL-side event-loop implementation (cold core, issue #1).
- The NDK. The compiler and GC never depend on the NDK; only final APK
  packaging does, and that step has three documented fallback paths
  (DESIGN.md §9.2).

## 9. Acceptance

The ABI contract is satisfied when: (a) this document is complete and reviewed;
(b) the Linux mock shim compiles and the runtime's lifecycle state machine runs
against it on the host; (c) the APK packager (done — see `src/android/`) can
package a placeholder `.so` plus manifest into a structurally valid, signed
APK.
